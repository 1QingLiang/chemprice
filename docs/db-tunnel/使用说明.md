# ChemPrice 数据库 · SSH 隧道方案

> 用途：在本地用 Navicat / DBeaver 等客户端查服务器数据库，**无需开放 3306 到公网**。
> 建立日期 2026-09-25 · 已实测打通（本机成功握手到服务器 MySQL 8.0.46）

---

## 一、为什么不直接开放外网

| 项 | 开放 3306 到公网 | SSH 隧道（本方案） |
|---|---|---|
| 数据库端口暴露 | ⚠️ 全网可达，24 小时被扫描爆破 | ✅ 保持关闭，外网探测不可达 |
| 数据传输 | 明文（除非另配 TLS） | ✅ SSH 全程加密 |
| 凭据存放 | 密码要写进客户端配置 | ✅ 不落盘，用时临时取 |
| 与现有安全加固 | ❌ 绕过 nginx 限流与行为识别 | ✅ 加固体系不受影响 |
| 爆炸半径 | 736 万行核心数据可被批量拖走 | ✅ 需先攻破 SSH 密钥 |

**结论**：隧道方案在安全性上完全优于开放端口，且使用体验差异很小（双击一个脚本）。

## 二、使用步骤

### 第 1 步：双击运行「数据库隧道.bat」

会弹出一个黑色窗口，显示：
```
[*] 正在建立隧道...（本窗口需保持打开）
```
**这个窗口必须一直开着**，关了隧道就断了。

### 第 2 步：双击「连接信息.bat」查看密码

密码不落盘保存，每次运行时从服务器临时读取并显示在窗口里。

### 第 3 步：在 Navicat 里新建连接

| 字段 | 值 |
|---|---|
| 连接名 | ChemPrice（本地隧道） |
| 主机名 | `127.0.0.1` |
| 端口 | `13306` |
| 用户名 | `cardplaza` |
| 密码 | 见第 2 步窗口中显示 |

> ⚠️ 主机名**必须**填 `127.0.0.1`，不要填服务器 IP —— 填 IP 就变成直连公网了，而公网是关着的。

### 第 4 步：用完关掉隧道窗口

Navicat 会立即断连，属正常现象。

## 三、技术细节

```
本机 127.0.0.1:13306
        │
        │  SSH 加密隧道（-L 本地端口转发）
        ▼
ubuntu@82.156.8.214
        │
        │  服务器内部回环
        ▼
   localhost:3306  (MySQL 8.0.46)
```

等价命令（想手动敲的话）：
```bash
ssh -N -L 13306:127.0.0.1:3306 ubuntu@82.156.8.214
```

参数说明：
- `-N` 不执行远程命令，只做端口转发
- `-L 13306:127.0.0.1:3306` 把本地 13306 转发到服务器的 3306
- `ServerAliveInterval=30` 每 30 秒发一次保活包，防止空闲被断
- `ExitOnForwardFailure=yes` 转发失败就直接退出（避免"看起来连上了其实没通"）

### ⛔ 一个实测踩到的坑

**不要加 `-f` 参数**（让 ssh 转到后台）。实测在本机 Git Bash 环境下，`ssh -f` 会立即退出且隧道不保持，
表现就是"命令返回成功，但端口连不上"。用普通前台方式最稳定。

## 四、常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 窗口提示"本地 13306 端口已被占用" | 上一个隧道窗口还没关 | 关掉旧窗口，或结束占用进程 |
| Navicat 报 "Can't connect to MySQL server" | 隧道窗口被关了 / 网络中断 | 重新双击隧道脚本 |
| 连接超时 | 服务器 SSH 不可达 | 先测试 `ssh ubuntu@82.156.8.214` 能否登录 |
| 想换个本地端口 | 13306 被别的程序占了 | 改脚本里的 `13306:127.0.0.1:3306` 前半部分 |

## 五、安全说明

1. **服务器 3306 依然只对本地开放**，云安全组未放行，外网不可达（已实测确认）。
2. **密码不写入任何文件** —— 采用「用时从服务器读取并临时显示」的方式。
3. **SSH 密钥认证**，无需密码登录；密钥在 `~/.ssh/id_rsa`。
4. 建议：**不要长期开着隧道**，用完就关，减少潜在暴露窗口。
