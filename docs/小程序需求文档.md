1. **MVP 范围已确定**：行情看板 + 商品报价 + 涨跌排行 + 标点地图 + 供需广场（含 3 类订阅消息）。

## 1. 背景与目标

### 1.1 现状：Web 平台已具备的能力

平台已是一个功能完整的化工价格数据与撮合系统，核心能力如下（详见附录 A）：

| 域 | 能力 |
|---|---|
| 数据 | 256 个在售品种、2,288 个报价点、覆盖 30 省级行政区 / 282 个城市 |
| 行情 | 看板、商品中心、商品详情（报价明细）、数据表、涨跌排行 |
| 分析 | 报价点分析、**标点地图**（全国→省→市→报价点逐级下钻 + 3 张分析图）、产品分布 |
| 工具 | 物性查询（含导出 PDF）、办公工具（197 个站点）、AI 智能问价 |
| 线索 | 供需广场、供应商企业认证 |
| 触达 | 每日邮件推送、新求购邮件通知、微信公众号（08:00 早报 / 16:00 今日行情） |
| 权限 | 数据权限（品种白名单，永久）、导出权限、**标点地图权限（可设有效期）**、开放 API（积分制） |
| 安全 | nginx 三层限流（auth/api/open/static）、BotDetectFilter 行为识别、登录失败锁定 |

### 1.2 为什么做小程序

1. **场景吻合**：看价、比价、找货源是典型的"碎片时间 + 手机"行为，Web 端需要打开浏览器并登录，链路长。
2. **触达闭环**：公众号（内容）→ 小程序（工具）是微信生态内的标准组合，公众号已有存量粉丝。
3. **转化成本更低**：微信一键登录免注册，是 Web 端账号密码注册无法比拟的。
4. **供需线索时效性**：求购/供应留言的即时提醒，是小程序相对 Web 的最大增量价值。

### 1.3 目标与成功指标

| 层级 | 指标 | 目标（上线 3 个月） |
|---|---|---|
| 北极星 | 周活跃用户（WAU） | 达到 Web 端周活的 40% |
| 获客 | 小程序新增用户 / 公众号粉丝转化率 | ≥ 8% |
| 留存 | 7 日留存 | ≥ 25% |
| 商业（若主体支持） | 付费转化率、标点地图开通数 | 待定价后设定 |
| 质量 | 首屏可交互 < 1.5s（4G）、崩溃率 < 0.5% | — |

### 1.4 非目标（本版明确不做）

- ❌ 管理端（用户管理、用户看板、AI 日志、定时服务监控、供应商审核）——手机端体验更差，留在 Web。
- ❌ 开放 API 控制台、办公工具（197 站点）—— 外链业务域名无法批量备案，见 5.9。物性查询与 PDF 导出列为 P2。
- ❌ 数据表批量导出 Excel —— 移动端价值低，且导出权限已有 Web 出口。
- ❌ 邮件推送设置 —— 与小程序消息能力重叠，本版只做订阅消息。

### 2.2 冲突一：**支付** → ✅ 已解决（D1 选定「借用他人主体」）

原冲突：曾同时选择「个人主体」与「小程序内订阅付费」，而个人主体小程序无法申请微信支付商户号，两者在规则上不能并存。

**当前决议**：改用**他人公司/主体**注册小程序 → 微信支付商户号可正常申请，**月/季/年订阅付费与标点地图单独开通均可实现**。

下表保留作为决策记录；已选 **B 借用他人主体**，对应的新增风险与操作规范见 **2.8**（新增，重点章节）。

| 方案 | 可行性 | 代价 |
|---|---|---|
| **A. 办个体工商户**（推荐） | ✅ 完全解锁 | 执照办理成本低（多地线上办理，部分免费）；后续需简易记账/零申报，年成本数百元 |
| B. 借用他人主体 | ⚠️ 技术上可行 | **收款进他人账户、账号法律归属他人、主体不可变更**，后续迁移/纠纷风险高 |
| C. 放弃小程序内支付 | ✅ 立刻可做 | 权限沿用后台人工开通（沿用现有 `enterprise_map_expire_date` 机制），付费留到 Web 或后续版本 |

> **原建议 A（保留备查）**：理由是"小程序主体不可变更，用个人主体先注册再改商用，只能注销重注册"。当前已选 **B**，因此请务必先落实 **2.8** 的 5 项规范。

### 2.3 冲突二：**服务类目** → ⚠️ 风险下降但未消失

改用公司主体后，**"类目可选范围太窄"的问题已解除**（企业/个体工商户可选类目远多于个人主体）。

但**金融类目是独立门槛**：微信类目表中有「金融业-证券、期货投资咨询」「股票信息服务平台」等，需要《增值电信业务经营许可证》《证券信息经营许可》一类资质 —— **你的公司主体同样拿不到**。你的核心内容是"化工原料价格行情数据"，仍存在被判入金融类目的风险。

**规避策略（规避金融化定位）**：

1. 申报类目**避开"金融业"大类**，优先「商业服务 → 信息查询」或「工具 → 查询」，把产品定位成"**化工原料价格查询工具 / 数据服务**"，而非"行情资讯平台"。
2. 全站文案红线（**列入审核自查清单**）：
   - ❌ 禁止出现：投资、理财、期货、证券、荐股、涨跌预测、行情分析报告、交易信号
   - ✅ 使用：原料价格、报价点、成交参考价、数据查询、仅供参考
3. 保留现有免责声明："数据来源：ChemPrice 化工价格平台 · 仅供行业参考"，并在小程序「我的 → 关于」固定展示。
4. **必须在 M0 用体验版实际提审验证类目**（借用主体场景下提审需对方配合），不要等到功能全做完才发现类目过不了。

### 2.4 冲突三：**域名 / 备案 / HTTPS（硬前置）**

小程序 `wx.request` **只允许请求已 ICP 备案的 HTTPS 域名**，且需在小程序后台配置为 request 合法域名。**IP 直连（`http://82.156.8.214/`）与 HTTP 一律不可用。**

现状：`chemprice.com` 解析到停放 IP、未指向本平台，且未备案 → **这是小程序开发的第一阻塞项**。

| 任务 | 说明 | 依赖 |
|---|---|---|
| 域名备案（ICP） | 需主体资质；个体工商户可备案（个人也可备案，但域名用途须与小程序一致） | 服务器在境内（已满足，腾讯云 82.156.8.214） |
| HTTPS 证书 | 备案通过后申请（腾讯云免费 DV 证书即可） | 域名解析到本机 |
| nginx 443 配置 | 现有 80 端口配置基础上增加 TLS | 证书 |
| 小程序后台配置 | request / uploadFile / downloadFile 合法域名 | HTTPS |

> 附带收益：备案 + HTTPS 后，**公众号"阅读原文"链接也可从 IP 换成域名**（当前为临时方案，只需改一处字段）。

### 2.5 冲突四：**账号体系打通**

- 小程序用户以 `openid` 标识。若要实现"公众号粉丝 = 小程序用户"的同一身份，需要 **UnionID**（须绑定微信开放平台账号）。**个人主体绑定开放平台受限**，个体工商户/企业可行。
- 因此本版按**独立账号体系**设计：小程序 `openid` → 绑定平台账号（手机号或账号密码一次绑定），不依赖 UnionID。

### 2.8 ⛔ 借用他人公司主体：操作规范与风险（动工前必读）

#### 2.8.1 风险清单与对策

| # | 风险 | 具体后果 | 对策 |
|---|---|---|---|
| R-A | **账号法律归属** | 小程序主体、微信支付商户号、绑定关系均归对方公司所有；对方可单方面找回、冻结、下架 | ① **管理员微信号必须用你自己的实名微信**（主体与管理员可以是不同人，**管理员身份才是实际控制权**）；② 书面约定账号使用权，禁止单方变更管理员/主体信息 |

| R-E | **资质配合度** | 备案、微信认证、部分类目提审都需要对方执照、法人信息、公章配合 | 一次性索取清单：营业执照、法人身份证、对公账户信息、公章配合承诺、法人扫脸配合 |

#### 2.8.2 必须落纸的 3 条（一页纸协议即可，重点是留痕）

1. **控制权**：小程序管理员为 Max 的实名微信；对方不得在未告知情况下变更管理员、主体信息、绑定关系；合作终止时的迁移或注销流程。
2. **资金**：支付资金归属、结算周期、发票开具方式、退款与争议责任划分。
3. **资产**：后端服务、数据库、代码、域名、用户数据全部归 Max（现状已在自有服务器上，协议中写明即可）。

#### 2.8.3 实际操作要点

| 事项 | 说明 |
|---|---|
| 注册 | 主体填**对方公司**，管理员填**你的微信号**；微信认证约 300 元/年（需对方对公打款或法人扫脸） |
| 微信支付 | 商户号签约主体**必须与小程序主体一致**（即对方公司）；结算账户是对公账户 |
| 公众号联动 | 现有公众号与小程序若主体不同，需走「关联小程序」流程（两端管理员分别确认），可行但需双方配合 |
| 备案 | 小程序备案 + 域名 ICP 备案均用对方主体提交，**周期 1–6 个工作日**（不含节假日） |

#### 2.8.4 与「自办个体工商户」的取舍

- 若对方是**可信赖的亲友/长期合作方**，借用在短期是可行的，但**长期成本**（信任维护、税务处理、迁移成本）通常高于自己办一个个体工商户。
- **推荐组合策略**：**短期借用 + 并行办理自有主体**。
- ⚠️ 但要注意：**小程序主体不可变更**，将来切换 = **重新注册 + 用户迁移**。因此这个决定**越早越好，不要等用户量起来再换**。

## 6. 权限与订阅模型

### 6.1 四类权限维度（沿用现有设计，小程序做裁剪）

| 维度 | 存储 | 小程序内表现 |
|---|---|---|
| 数据权限（品种白名单） | `data_permission` | 控制可见品种；**永久有效** |
| 导出权限 | `sys_user.export_permission` | 小程序内**不使用**（无导出） |
| 标点地图 | `sys_user.enterprise_map_enabled` + `enterprise_map_expire_date` | 控制地图 Tab；**支持有效期** |
| 开放 API | `sys_user.open_api_enabled` | 小程序内不可见 |

> ⚠️ 复用时注意：现有后端区分「业务错误码」与 HTTP 状态码 —— `Result<T>` 会以 **HTTP 200 + `code`** 返回业务错误，小程序端**必须判 `code`**，不能只看 `statusCode`。

### 6.2 订阅套餐设计（依赖 D1/D2）

| 套餐 | 周期 | 建议权益 |
|---|---|---|
| 基础 | 月 / 季 / 年 | 数据权限（全部品种）+ 看板 + 商品 + 涨跌 |
| 专业 | 月 / 季 / 年 | 基础上 + **标点地图** |
| 单点 | — | 仅开通标点地图（按现有"单独开通 + 有效期"逻辑） |

定价策略与是否分档，需在 D2 拍板后单独出「定价与权益表」，本文档不预设金额。

### 6.3 到期与续期

**完全复用现有语义**：`NULL = 永久`；**到期日当天仍有效，次日起失效**；失效后展示红色"已到期"+ 续期引导。小程序端只需消费同一套接口字段（`expireDate / daysLeft / expired`），避免两端口径不一致。

### 6.4 支付流程（D2 已定：做）

```
小程序 → 后端下单（生成订单号，写入 orders 表）
      → 后端调微信支付统一下单（需商户号 + 商户证书）
      → 小程序 wx.requestPayment
      → 微信异步回调后端 → 校验签名 → 更新权限（写 enterprise_map_expire_date / 套餐有效期）
      → 小程序查询订单状态并刷新权限
```

关键点：**回调必须幂等**；订单与权限变更**同一事务**；必须做「支付成功但客户端未收到」的对账补偿。

**资金与合规（借用主体下必须提前明确）**：

- 款项进入**对方公司对公账户**（微信支付签约主体必须与小程序主体一致），结算周期与开票方式写入 2.8.2 协议。
- 支付**商户号后台权限、API 密钥、商户证书应由你掌握**，防止对方单方修改结算账户。
- ⛔ **不做二清**：只收自营的「数据订阅 / 信息服务费」；若替供应商代收货款再向下结算，属违规经营。
- 必须提供**退款**能力，并在购买页前置展示订阅类退款政策。

## 7. 技术方案

### 7.1 架构总览

```
微信小程序 (原生 / uni-app)
   │  HTTPS + 已备案域名
   ▼
nginx  (复用现有配置，新增 443 / TLS)
   │  限流 zone：cp_auth / cp_api / cp_open / cp_static
   ▼
Spring Boot 3.5.6  (复用现有后端，新增 /api/wx/** 与少量聚合接口)
   │
   ├── MySQL longzhong（复用现有库 + 新增：wx_user 绑定表、orders 表）
   └── 预计算表 enterprise_point_stat（复用，每日 06:40 刷新）
```

**结论：后端与数据层 100% 复用**，仅新增登录绑定、支付、订阅消息三类能力。

### 7.2 技术选型对比

| 方案 | 优势 | 劣势 | 结论 |
|---|---|---|---|
| **原生小程序**（WXML/WXSS/JS） | 性能最好、API 最全、审核最稳 | 与现有 Vue3 代码**零复用**；地图/图表需另写 | 追求性能与稳定性可选 |
| **uni-app（推荐）** | 语法接近 Vue3，**现有 Vue3 组件与逻辑可部分复用**；一套代码可扩展 H5/App；生态成熟 | 部分原生能力需条件编译；包体略大 | ✅ **推荐** |
| Taro | React 语法 | 与现有 Vue 技术栈不符 | 不推荐 |

### 7.3 微信登录与账号绑定流程

```
1) 小程序 wx.login() → code
2) POST /api/wx/login { code }
   → 后端 code2session 换 openid/session_key
   → 查 wx_user 表：已绑定？返回 JWT（与 Web 同一套 JWT 体系）
                 未绑定？返回 bind_required
3) 未绑定 → 绑定页（账号密码 / 手机号+验证码）→ POST /api/wx/bind
   → 校验平台账号 → 写 wx_user(openid, user_id) → 返回 JWT
```

### 7.4 新增后端接口清单（预估）

| 接口 | 方法 | 说明 | 复用度 |
|---|---|---|---|
| `/api/wx/login` | POST | code 换 openid + 登录态 | 新 |
| `/api/wx/bind` | POST | 绑定平台账号 | 新 |
| `/api/wx/unbind` | POST | 解绑（P2） | 新 |
| `/api/wx/subscribe` | POST | 记录订阅授权（模板 + 次数） | 新 |
| `/api/wx/pay/order` | POST | 下单（D2=是） | 新 |
| `/api/wx/pay/callback` | POST | 支付回调（幂等） | 新 |
| 现有行情/商品/涨跌/地图/供需接口 | GET | **直接复用** | 复用 |
| `/api/enterprise-map/points/*` | GET | 复用现有预计算表接口 | 复用 |

> 建议：现有接口统一在 `/api/**`，小程序只需配置同一域名，无需为小程序单独开一套 API。

### 7.5 图表与地图改造（主要技术难点）

| 难点 | 现状 | 方案 | 风险 |
|---|---|---|---|
| 地图渲染 | Web 用 ECharts + `cn_city_geo.js`（2.38MB） | 方案一：`ec-canvas`（ECharts 小程序版）+ 按需加载省份 GeoJSON；方案二：改用地图组件/自绘 canvas | 主包体积上限 2MB（分包 20MB）→ **GeoJSON 必须分包或按省懒加载** |
| 移动端手势 | Web 是"点击省/市" | 保留点击下钻，**禁用双击下钻**避免与缩放手势冲突 | 需真机验证 |
| 矩阵热力图 | 12×12 表格 | 移动端横向滚动 + 固定列 | 交互需实测 |
| 首屏性能 | Web 主包 410KB（gzip 后） | 小程序分包 + 骨架屏 + 数据分页 | — |

### 7.6 安全与限流复用

现有三层防护可直接复用，但**限流维度需增加 openid 维度**（否则同一 NAT 出口的多个用户会互相挤占配额）：

1. nginx 层：为 `/api/wx/**` 单独建 zone（按 IP）。
2. 应用层：按 `user_id` / `openid` 限流（令牌桶），比 IP 更精准。
3. 行为识别：`BotDetectFilter` 保留；小程序请求需带合法 JWT，建议对无 token 的高频调用直接拦截。
4. **代码签名/接口加密不做**（成本高收益低），但需保证 JWT 不过期逻辑可被小程序安全刷新。

## 11. 验收要点

1. **功能**：本文档第 5 章每条 FR 的"验收标准"逐条通过，并输出用例表（建议做成可勾选清单）。
2. **一致性**：小程序与 Web 在**价格、涨跌、地图点数、权限状态**四处数据必须逐项比对一致（抽样 ≥ 20 条）。
3. **权限**：未开通 / 已开通 / 已到期 / 到期前 7 天，四种状态分别验证（对应现有 31 项接口 + 23 项浏览器验收的思路）。
4. **边界**：休市日、无数据、接口 500、断网、token 过期，五种异常态各有兜底。
5. **合规**：首次启动协议勾选、免责声明可见、全文无投资建议类表述（关键词扫描）。
6. **性能**：真机首屏 < 1.5s；地图下钻 < 800ms。

## 附录 B · 与现有系统的对接注意事项（开发必读）

1. **`Result<T>` 业务码**：后端业务错误以 HTTP 200 + `{code,message,data}` 返回，小程序端必须判 `code`。
2. **权限判定单一来源**：标点地图可用性必须走后端 `emapAuth`，禁止小程序端自行组合 `switchOn && !expired`。
3. **休市日**：非交易日不更新行情数据，前端必须展示"数据截止 X 日"，避免误报为异常。
4. **限流**：现有 zone 已按真实基线校准（auth 10r/m、api 600r/m 等），小程序上线前需重新评估并增加 openid 维度。
5. **域名改造是全局的**：备案 + HTTPS 完成后，公众号"阅读原文"、邮件推送链接中的 IP 均可替换为域名（各一处）。
