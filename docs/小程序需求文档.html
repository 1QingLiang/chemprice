0. 一页结论（TL;DR）

  1. MVP 范围已确定：行情看板 + 商品报价 + 涨跌排行 + 标点地图 + 供需广场（含 3 类订阅消息）。
  2. ✅ 主体路径已定：借用他人公司/主体。原先「个人主体 + 订阅付费」互斥的问题因此解除 —— 该选择一次性解锁微信支付、web-view、手机号一键绑定、UnionID、更宽的服务类目。
  3. ⛔ 主体是他人公司后，风险重心从"技术"转到"关系"：账号法律归属、收款进他人对公账户、对方可随时收回控制权。→ 第 2.8 节列出 5 条落地规范，动工前必须先落纸。
  4. 仍有 2 个硬前置，与谁是主体无关：① 已 ICP 备案的域名 + HTTPS（IP + HTTP 直连在小程序里不可用）；② 小程序本身必须完成工信部备案。两项都用对方公司主体去办，需要对方配合提供执照、法人信息与盖章材料。
  5. ⛔ 资金红线：只收「信息服务费 / 数据订阅费」这类自营服务费。若替供应商代收货款再向下结算，构成二次清算（二清），属违规经营，务必避免。

1.2 为什么做小程序

  1. 场景吻合：看价、比价、找货源是典型的"碎片时间 + 手机"行为，Web 端需要打开浏览器并登录，链路长。
  2. 触达闭环：公众号（内容）→ 小程序（工具）是微信生态内的标准组合，公众号已有存量粉丝。
  3. 转化成本更低：微信一键登录免注册，是 Web 端账号密码注册无法比拟的。
  4. 供需线索时效性：求购/供应留言的即时提醒，是小程序相对 Web 的最大增量价值。

2.2 冲突一：支付 → ✅ 已解决（D1 选定「借用他人主体」）

原冲突：曾同时选择「个人主体」与「小程序内订阅付费」，而个人主体小程序无法申请微信支付商户号，两者在规则上不能并存。

当前决议：改用他人公司/主体注册小程序 → 微信支付商户号可正常申请，月/季/年订阅付费与标点地图单独开通均可实现。

下表保留作为决策记录；已选 B 借用他人主体，对应的新增风险与操作规范见 2.8（新增，重点章节）。

方案可行性代价
A. 办个体工商户（推荐）✅ 完全解锁执照办理成本低（多地线上办理，部分免费）；后续需简易记账/零申报，年成本数百元
B. 借用他人主体⚠️ 技术上可行收款进他人账户、账号法律归属他人、主体不可变更，后续迁移/纠纷风险高
C. 放弃小程序内支付✅ 立刻可做权限沿用后台人工开通（沿用现有 enterprise_map_expire_date 机制），付费留到 Web 或后续版本
原建议 A（保留备查）：理由是"小程序主体不可变更，用个人主体先注册再改商用，只能注销重注册"。当前已选 B，因此请务必先落实 2.8 的 5 项规范。

2.3 冲突二：服务类目 → ⚠️ 风险下降但未消失

改用公司主体后，"类目可选范围太窄"的问题已解除（企业/个体工商户可选类目远多于个人主体）。

但金融类目是独立门槛：微信类目表中有「金融业-证券、期货投资咨询」「股票信息服务平台」等，需要《增值电信业务经营许可证》《证券信息经营许可》一类资质 —— 你的公司主体同样拿不到。你的核心内容是"化工原料价格行情数据"，仍存在被判入金融类目的风险。

规避策略（规避金融化定位）：

  1. 申报类目避开"金融业"大类，优先「商业服务 → 信息查询」或「工具 → 查询」，把产品定位成"化工原料价格查询工具 / 数据服务"，而非"行情资讯平台"。
  2. 全站文案红线（列入审核自查清单）：
  3. ❌ 禁止出现：投资、理财、期货、证券、荐股、涨跌预测、行情分析报告、交易信号
  4. ✅ 使用：原料价格、报价点、成交参考价、数据查询、仅供参考
  5. 保留现有免责声明："数据来源：ChemPrice 化工价格平台 · 仅供行业参考"，并在小程序「我的 → 关于」固定展示。
  6. 必须在 M0 用体验版实际提审验证类目（借用主体场景下提审需对方配合），不要等到功能全做完才发现类目过不了。

2.4 冲突三：域名 / 备案 / HTTPS（硬前置）

小程序 wx.request 只允许请求已 ICP 备案的 HTTPS 域名，且需在小程序后台配置为 request 合法域名。IP 直连（http://82.156.8.214/）与 HTTP 一律不可用。

现状：chemprice.com 解析到停放 IP、未指向本平台，且未备案 → 这是小程序开发的第一阻塞项。

任务说明依赖
域名备案（ICP）需主体资质；个体工商户可备案（个人也可备案，但域名用途须与小程序一致）服务器在境内（已满足，腾讯云 82.156.8.214）
HTTPS 证书备案通过后申请（腾讯云免费 DV 证书即可）域名解析到本机
nginx 443 配置现有 80 端口配置基础上增加 TLS证书
小程序后台配置request / uploadFile / downloadFile 合法域名HTTPS
附带收益：备案 + HTTPS 后，公众号"阅读原文"链接也可从 IP 换成域名（当前为临时方案，只需改一处字段）。

2.5 冲突四：账号体系打通

  • 小程序用户以 openid 标识。若要实现"公众号粉丝 = 小程序用户"的同一身份，需要 UnionID（须绑定微信开放平台账号）。个人主体绑定开放平台受限，个体工商户/企业可行。
  • 因此本版按独立账号体系设计：小程序 openid → 绑定平台账号（手机号或账号密码一次绑定），不依赖 UnionID。

  • 若对方是可信赖的亲友/长期合作方，借用在短期是可行的，但长期成本（信任维护、税务处理、迁移成本）通常高于自己办一个个体工商户。

6.4 支付流程（D2 已定：做）

小程序 → 后端下单（生成订单号，写入 orders 表）
      → 后端调微信支付统一下单（需商户号 + 商户证书）
      → 小程序 wx.requestPayment
      → 微信异步回调后端 → 校验签名 → 更新权限（写 enterprise_map_expire_date / 套餐有效期）
      → 小程序查询订单状态并刷新权限

关键点：回调必须幂等；订单与权限变更同一事务；必须做「支付成功但客户端未收到」的对账补偿。

资金与合规（借用主体下必须提前明确）：

  • 款项进入对方公司对公账户（微信支付签约主体必须与小程序主体一致），结算周期与开票方式写入 2.8.2 协议。
  • 支付商户号后台权限、API 密钥、商户证书应由你掌握，防止对方单方修改结算账户。
  • ⛔ 不做二清：只收自营的「数据订阅 / 信息服务费」；若替供应商代收货款再向下结算，属违规经营。
  • 必须提供退款能力，并在购买页前置展示订阅类退款政策。

7.6 安全与限流复用

现有三层防护可直接复用，但限流维度需增加 openid 维度（否则同一 NAT 出口的多个用户会互相挤占配额）：

  1. nginx 层：为 /api/wx/** 单独建 zone（按 IP）。
  2. 应用层：按 user_id / openid 限流（令牌桶），比 IP 更精准。
  3. 行为识别：BotDetectFilter 保留；小程序请求需带合法 JWT，建议对无 token 的高频调用直接拦截。
  4. 代码签名/接口加密不做（成本高收益低），但需保证 JWT 不过期逻辑可被小程序安全刷新。

附录 B · 与现有系统的对接注意事项（开发必读）

  1. Result<T> 业务码：后端业务错误以 HTTP 200 + {code,message,data} 返回，小程序端必须判 code。
  2. 权限判定单一来源：标点地图可用性必须走后端 emapAuth，禁止小程序端自行组合 switchOn && !expired。
